# 0.6.0 — 기다릴 선수가 있고, 이겨야 할 경기가 있는 커리어

## 진행 방식

홈의 **진행 중 멈추는 보고**는 기본적으로 중요한 보고만 대상으로 한다. 일반 훈련·경기·관찰 소식은 읽지 않은 상태로 유지하며 지난 7일 브리핑에서 최근 8개를 바로 열 수 있다. 기존 수신함의 보관 한도와 전체 보고 열람도 유지한다. 모든 보고마다 멈추고 싶으면 `모든 보고`로 바꾼다.

필수 면담, 유효한 감독·선수·코치 계약 답변, 현금/선수 트레이드 제안, 부상과 드래프트 등은 중요 보고로 취급한다. 연전 위임은 읽은 계약이라도 미처리 답변이 있으면 시작하지 않는다. 일반 진행에서 보고를 읽는 것과 계약을 체결하는 것은 별도 동작이다.

반복 인터뷰는 기본적으로 코치가 담당하며 `직접 답하기`로 바꿀 수 있다. 코치는 기존 상황별 답변과 선수 반응을 사용한다. 경기 전 같은 대화의 중복 보상은 없고, 경기 후 대화는 다음 진행 명령에서 처리한다. 연전 위임에서는 경기 전후 인터뷰를 모두 함께 처리한다.

## 경기를 보는 세 가지 방법

- **모든 타석**: 기존 중계를 그대로 본다.
- **승부처만 지휘**: 경기 준비에서 선택하거나 경기 중 중계 설정을 바꾼다. 이미 진행한 상황을 기준으로 득점권, 7회 이후 3점 이내 접전, 지명한 육성 선수의 타석·등판을 보여 준다. 중요한 타석 전에는 기존 기회·위기 자동 일시정지와 사인·카드를 사용할 수 있다. 아직 진행하지 않은 안타·홈런 여부로 장면을 고르지 않는다.
- **이번 연전 맡기기**: 오늘 경기부터 같은 상대와 최대 3경기를 현재 명단·투수 계획으로 코치에게 맡긴다. 모달에서 내용을 확인하고 시작한다. 짧은 시즌의 일반 연전은 2경기다. 서버 명령 하나는 경기 최대 1개 또는 하루만 진행하며 매번 저장한다. 카드·증강은 기존 양 팀 코치 로직으로 사용한다.

연전은 다른 상대·라운드에 도달하거나 필수 면담·계약·중요 보고가 생기면 끝난다. 우천과 이동일을 포함해 최대 14일까지만 진행한다. 중단 버튼은 진행 중 요청의 저장 후 작동하고, 브라우저를 나가면 다음 요청을 보내지 않는다. 저장된 진행은 `위임 이어가기`로 재개할 수 있다. 출전 계획에 미저장 수정이 있으면 먼저 저장하도록 안내한다.

## 내가 믿는 선수

홈의 `육성 선수 지명` 모달에서 우리 구단의 23세 이하 선수 최대 3명을 선택한다. 목표는 1군 선발 3경기, 안타 5개, 홈런 1개, 탈삼진 5개 중 포지션에 맞게 고른다. 지명은 등록·선발·훈련을 자동 변경하지 않는다.

실제 정규시즌·포스트시즌 박스스코어로 출전과 기록을 계산한다. 첫 출전·선발·안타·홈런·탈삼진과 목표 달성을 홈과 경기 결과 보고에 남긴다. 연습경기는 제외한다. 첫 목표 달성 때 사기 +3(최대 100), 감독과의 관계 +2, 감독 업적을 한 번 부여한다. 잠재력이나 타격 결과를 직접 올리지 않는다.

지켜보기 해제 후 다시 지명해도 기존 목표와 누적 기록을 유지한다. 목표 보상을 반복해서 받을 수 없다. 저장 크기를 제한하기 위해 전체 커리어의 지명 이력은 30명까지 보관한다. 경기별 장면은 기존 경기 아카이브를 사용한다.

## 라이벌전과 팬 반응

실제 저장된 최근 맞대결 2연패, 이전에 감독을 맡은 구단과의 재회, 상위권 팀과 2경기 차 이내 순위 경쟁에서 경기의 의미를 안내한다. 우선순위는 설욕전 → 옛 구단 → 순위 경쟁이다. 경기 시작 시 안내를 고정하고 결과 보고에 실제 승패와 함께 남긴다.

이 경기에서 승리하면 팬 열기 +3, 패배하면 −2, 무승부는 유지한다. 열기는 구단별 현재 값 20~80 범위이며 다른 구단에 취임하면 50에서 시작한다. 다음 홈 경기 수입에 최대 ±6%로 반영하고 같은 경기의 재저장은 중복 적용하지 않는다. 이야기 문구 자체로 승패를 정하거나 임의의 선수를 약화시키지 않는다.

## 별도 도전 저장

홈 또는 새 커리어의 `짧은 도전 커리어`에서 들어간다. 일반 커리어 1개와 도전 커리어 1개를 같은 인증 소유자 아래 서로 다른 저장 영역에 둔다. 새 도전은 이전 도전만 교체하며, 본 커리어의 선수·계약·진행 중 경기·기록은 유지한다. 같은 게스트 복구 키로 두 영역을 복구할 수 있다. 탭별 선택은 sessionStorage에 저장하고 전환 시 화면을 새로 불러와 요청과 상태가 섞이지 않게 한다.

| 도전 | 시작 조건 | 성공 조건 |
| --- | --- | --- |
| 열 경기의 기적 | KBO 구단 선택, 9월 1일 시작, 20경기 10승 10패의 6위, 5위와 3경기 차, 각 구단 정규시즌 10경기 남음 | 실제 남은 일정 종료 후 상위 5위 진출 |
| 약체의 반란 | 키움 히어로즈 지정, 단축 시즌으로 시작 | 두 시즌 안에 상위 5위 진출 |

단축 KBO 시즌은 구단별 정규시즌 18경기이며 포스트시즌은 추가된다. 10경기 도전의 시작 순위와 앞선 20경기 성적은 가상 상황임을 화면에 명시한다. 승·패와 득·실점 합계는 균형을 맞추되, 가상의 과거 선수 기록이나 경기 아카이브를 만들지 않는다. 감독 승패에도 시작 성적을 새 결과로 더하지 않는다. 시작 후 경기·날씨·선수 변경은 기존 서버 엔진을 사용한다. 취소 경기는 경기 수에 포함하지 않으며 재편성 후 실제 정규시즌 종료 시 성공 여부를 확정한다. 도전 구단을 떠나면 도전은 종료된다.

## 수정 위치와 검증

- `packages/shared/src/career-pace.ts`: 서버와 화면이 공유하는 중요 보고 판정.
- `packages/shared/src/career-engagement.ts`, `match-highlights.ts`: 저장 계약·공용 이야기 및 승부처 조회.
- `apps/api/src/domain/career-engagement.ts`, `series-delegation.ts`, `career-challenge.ts`: 실제 경기 기록·보상·위임·도전 변경.
- `apps/api/src/auth/career-slot.ts`, `infra/cloudflare/auth.ts`: 인증된 소유자에서만 도전 저장 ID를 유도. 임의 사용자 ID는 받지 않는다.
- `useCareerExperience`, `useChallengeCareer`, `useSeriesDelegation`, `useMatchWatchMode`: 화면 상태·비동기 진행·자원 정리. 화면 구성과 `career-experience.css`는 분리한다. Redux/useReducer는 추가하지 않는다.

D1 테이블·카탈로그 이관·외부 API는 추가하지 않는다. 카탈로그는 `world-2026-09-14-v17`, 호스팅 프로젝트는 기존 식별자를 유지한다. 도전 데이터도 기존 서버 저장·revision·요청 ID 중복 방지·경기 아카이브 경로를 사용한다. 슬롯마다 독립적인 읽기/쓰기이며 연전도 한 번에 시즌 전체를 시뮬레이션하지 않는다.

회귀 검증은 중요/전체 보고 선택, 실제 유망주 기록과 한 번만 지급되는 보상, 실제 라이벌 승패, 균형 잡힌 시작 순위와 남은 10경기, 일정 종료 명령의 즉시 목표 확정, 양 팀 카드가 있는 경기별 위임, 계약/부상 중단, 미래 결과를 읽지 않는 승부처, D1 저장·재시도·다른 소유자 격리·일반 진행 경기 보존·도전만 있는 게스트 복구를 포함한다. PC/모바일 화면의 실제 조작 내용과 최종 배포 결과는 `WORKLOG.md`에 기록한다.

실제 리그 규칙 전체의 재현이나 난이도 균형의 장기 검증을 의미하지 않는다. 도전 종류는 위 두 가지이며 임의 시나리오 편집기·온라인 경쟁·다중 도전 슬롯은 제공하지 않는다.
