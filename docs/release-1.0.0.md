# DUGOUT 1.0.0 — 영입 경쟁, 선수의 변화, 구단의 기록

0.7.0 이후 실제로 선택하고 결과를 남기는 세 기능을 추가했다. 기존 커리어를 초기화하지 않고 이어서 사용할 수 있다. 기존 사인/카드/증강, 코치 경기 위임, 계약, 포스트시즌, 날씨, 전술 대응과 주전 경쟁을 유지한다.

## 플레이 경로

| 기능 | 위치 | 선택과 결과 |
| --- | --- | --- |
| 마감 영입 경쟁 | 홈 안내 → 트레이드 센터 | 상대 구단의 선수·현금 제안을 보고 맞제안/수정. 최종 확정 전에는 선수나 돈이 이동하지 않는다. |
| 타격·투구 폼 개조 | 선수 상세 → 성장 → 개조 방향 선택 | 야수 3종/투수 2종 중 선택. 훈련 12일 후 실제 능력 상승과 감소를 함께 적용한다. |
| 구단 기록실 | 상단 구단 이름 → 기록실 · 명예의 전당 | 시즌 성적/우승/시즌의 주역을 보관하고, 실제 공식 경기에 제목을 붙여 간직한다. |

선수와 방향을 고르는 작업은 모달에서 한다. 상호작용과 요청은 커스텀 훅, 화면은 재사용 패널에 두고 게임 변경은 인증된 서버 명령으로만 처리한다. 공개 버전과 빌드 식별자 표시는 기존 컴포넌트를 유지한다.

## 마감 영입 경쟁

기존 리그 마감일의 마지막 7일에 한 번, 성사 가능한 실제 경쟁 제안을 최대 3건 생성한다. 4개 판매 구단 × 3명 매물 × 4개 구매 구단 × 8명 교환 후보로 검색 범위를 제한한다. 같은 리그 실제 소속, 부상/대표팀, 선수 가치, 포지션/인원, 구단 예산을 확인한다. 후보가 없으면 매물을 꾸며내거나 다시 추첨하지 않는다.

마감일까지 최대 3일의 결정 기간을 둔다. 화면의 **최종 확정일까지** 영입을 완료해야 한다. 표시된 **매각 결정일로 날짜를 넘기면** 유효한 경쟁 제안이 실제 AI 구단 간 교환으로 확정된다. 우리 제안이 우세해도 최종 확정을 누르지 않으면 영입하지 않은 상태다.

기존 트레이드와 같은 가치 계산 및 현금 30% 상한을 사용한다. 구단의 역제안이 있으면 실제로 요구한 선수와 현금을 보여 준다. 일반 트레이드 제안 및 현금 영입으로 경쟁을 우회할 수 없다. 이동/부상/시즌 종료/퇴임으로 무효가 된 제안은 취소하고, 완료한 영입을 다시 실행하지 않는다.

실시간 경매나 계속 올라가는 AI 입찰은 아니다. 게임 날짜로 진행하는 규칙 기반 경쟁이며 국가별 실제 계약 제도를 모두 재현하지 않는다.

## 타격·투구 폼 개조

| 개조 | 완성 시 최대 상승 | 대가 |
| --- | --- | --- |
| 장타형 스윙 | 장타 +4 | 컨택 −2 |
| 짧고 간결한 스윙 | 컨택 +3 | 장타 −2 |
| 수비 중심 몸 만들기 | 수비 +4 | 장타 −2 |
| 힘으로 누르는 투구 | 구위 +3 | 제구 −2 |
| 간결한 투구폼 | 제구 +3 | 구위 −1.5 |

훈련하는 날 12일을 채우면 한 번 반영한다. 선택 당일, 부상/대표팀/컨디션 회복/개인·팀 휴식은 진행하지 않는다. 능력 상승 여력이 적으면 상승과 감소를 같은 비율로 줄인다. 완성 전 취소에는 능력 변화가 없다.

선수별 시즌당 1회, 구단 동시 3명이다. 취소해도 같은 시즌에 다시 시작할 수 없다. 시즌을 걸쳐 완료/취소하면 종료 시즌도 사용한 것으로 처리한다. 이적 후 미완성 계획은 종료하고, 완성 정보와 실제 능력은 세계 선수 상태로 보존한다. 성장/노화/시즌 평가의 기존 규칙은 계속 적용된다. 경기 중에는 변경할 수 없고 시작할 때 고정하는 경기 입력에 바뀐 능력이 들어간다.

## 구단 기록실

시즌 종료 시 현재 소속 구단의 실제 정규 순위/승패/최종 우승 구단/감독과 타자·투수 주역을 한 번 기록한다. 타자는 홈런·타점·안타, 투수는 승리·탈삼진을 기준으로 고른다. 선수 수치는 **종료 시점 소속 선수의 시즌 누적 기록**이며 이적 전 기록도 포함한다. 현실의 은퇴 선수 헌액이나 실존 구단의 과거 역사를 의미하지 않는다.

기억할 경기는 해당 구단이 치른 공식 경기에서 선택한다. 경기 점수·MVP·소속은 저장된 결과를 사용하며 제목만 직접 적는다. 구단별 12경기, 커리어 전체 120경기, 제목 80자, 시즌 요약 100건의 보관 한도를 둔다. 경기 로그 전체를 복제하지 않는다. 새 시즌이나 감독 이동에도 구단별 기록을 유지한다.

과거 `past` 기록에는 당시 소속 구단/선수 자료가 없으므로 이미 끝난 시즌의 명예의 전당을 임의로 복원하지 않는다. 이번 업데이트 후 종료하는 시즌부터 보관하며, 업데이트 당시 아직 종료 상태인 시즌은 다음 변경/새 시즌 진행 때 기록한다.

## 수정 위치와 검증

- 공유 규칙: `packages/shared/src/{deadline-market,player-remodel,club-legacy}.ts`
- 서버: `apps/api/src/domain/{deadline-market,player-remodel,club-legacy}.ts`, 기존 트레이드/일별 육성/시즌 종료와 통합.
- 화면: `features/market/deadline-market-panel.tsx`, `features/players/player-remodel-panel.tsx`, `features/clubs/club-legacy-panel.tsx` 및 각각의 `use-*` 훅/스타일.
- 단위/통합: `tests/{deadline-market,player-remodel,club-legacy}.test.mjs`, `tests/api-database.test.mjs`. 소유권, 재요청, 확정 시 예산/선수 교환, 위조 입력 차단, 훈련과 시즌 경계, 실제 경기 입력, 기록 보존을 검증한다.
- 브라우저: 격리한 프로덕션 Worker/D1의 PC/390px 모달, 실제 API 저장, 새로고침 유지, 글자 대비 및 가로 넘침을 확인했다. 장기 난이도 균형이나 모든 리그/저장 상태의 브라우저 검증을 의미하지 않는다.

새 D1 테이블·전체 아카이브 조회를 추가하지 않았다. 런타임 카탈로그 v17, `.openai/hosting.json` 정체성, 기존 배포 경로와 요금제를 유지한다. 홍보 메시지 게시나 외부 발송은 이번 작업에 포함하지 않는다.
