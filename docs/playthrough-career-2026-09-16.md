장기간 조건은 로컬 D1에 테스트 상태를 준비한 후 실제 화면의 버튼·면접·서명으로 진행했다. 조건을 준비한 경질·시즌 종료를 공개 서버에서 자연스럽게 달성한 성적이라고 해석하면 안 된다. 공개 테스트 브라우저가 재시작되어 쿠키가 사라진 뒤에는 저장한 관찰 결과를 보존하고 로컬 검증을 이어갔다. 이번 공개 구직 커리어의 시즌 전체를 완주했다고 주장하지 않는다.

## 수정한 문제

1. **계약 만료가 사퇴로 표시됨**: `nonrenewal`을 우선 판정해 홈·경력·수신함의 만료 사유를 일치시켰다. 자진 사퇴와 계약 중 경질은 구분한다.
2. **퇴임 순위가 새 시즌 기준으로 기록됨**: 순위와 이사회 기준을 초기화하기 전에 계약 만료를 처리한다. 테스트에서 종전 1위가 3위로 바뀌던 기록이 1위로 보존된다.
3. **무직에게 신인 지명을 안내함**: 시즌 시작 보고가 현재 고용 상태를 확인해 무직에게 채용 센터를 안내한다.
4. **한 채용에 옛 메일이 모두 처리 필요로 집계됨**: 최신 연락 한 건만 결정 대상으로 표시한다. 이사회가 수정 제안을 검토 중이면 날짜 진행을 막는 결정으로 취급하지 않는다. 지난 메일은 계속 열람할 수 있다.
5. **새 구단에서 이전 구단 경기·최근 성적을 보여줌**: 삼성으로 옮긴 뒤 KIA의 3승 1패가 최근 경기로 표시됐으나 삼성 순위는 2승 2패였다. 현재 구단의 경기만 모으는 공통 함수를 홈·일정·주간 브리핑·경기 전 인터뷰·맞대결 안내에 적용한다. 새 구단의 취임 전 점수 기록도 포함하고 중복은 제거한다. 원래 경기 아카이브는 삭제하지 않는다.
6. **취임 전 점수만 있는 경기에서 리플레이를 요청함**: 플레이 기록이 없는 경기는 ‘점수 기록’으로 표시한다. 존재하지 않는 상세 기록 요청을 막고, 아카이브가 있는 기존 경기의 다시보기는 유지한다.

이미 저장된 과거 퇴임 순위를 추정해 소급 변경하지 않는다. 날짜가 다음 해로 넘어가는 겨울 리그 경기를 연도 문자열만으로 제외하지 않는다. D1 스키마·카탈로그와 기존 저장을 유지한다.

## 재미와 흐름 평가

- **구직·협상은 선택할 이유가 있다.** 지원 구단, 공개/비공개 접촉, 순위 약속, 예산 요청과 연봉 역제안이 이어진다. 실제 면접 답변·계약 조건·예산 변화가 남는다. 새 직장을 잡고 이전 팀을 상대하는 흐름은 커리어의 동기가 될 수 있다.
- **카드·사인은 위기에서 판단할 여지를 준다.** 공격·수비 카드 사용 시점이 갈리고, 상대 증강을 먼저 막을지 제구를 높일지 선택했다. 사인을 내도 실패하므로 결과를 기다리는 긴장감은 있다. 한 경기로 확률 균형이나 작전의 인과 효과를 평가하지는 않았다.
- **면접의 반복을 1.0.5에서 개선했다.** 이전 성적·계약 목표·경질/만료 기록에 따라 첫 감독, 성과 재현, 재도전, 복귀 질문과 답변을 구분한다. 문항 수는 6개를 유지하고 실제 선임 평가와 예산 요청 판단을 바꿨다. 같은 경쟁 후보 기준에서도 경력에 맞는 답변에 따라 채용/탈락이 갈리는 것을 검증했다.
- **연속 위기 조작을 1.0.5에서 줄였다.** 기회·위기 모달에서 ‘이번 이닝만 코치에게’를 누르면 작전/카드를 맡기고 다음 이닝에 지휘권을 돌려받는다. 실제 브라우저에서 1회 위임 → 2회 복귀 → 2회 재위임 → 3회 직접 지휘를 확인했다. 카드의 1회 소비와 과거 타석 보존도 검증했다.
- **휴가 복귀 보고를 1.0.5에서 정리했다.** 복귀 요약에서 미처리 답변과 중요한 소식을 먼저 열고 경기/일반 보고는 접어서 볼 수 있다. 실제 7일 휴가 후 5경기 3승 2패, 결정 2건, 중요 소식 2건, 일반 보고 15건을 확인하고 등록 추천을 열어 보류 처리했다. 이 수치는 앞선 1.0.3 플레이와 다른 새 테스트 커리어의 결과다.
- **팀 운영과 경쟁의 균형은 추가 표본이 필요하다.** 이전 KIA 우승 커리어, 이번 롯데의 초반 1승 2패, 휴가 KIA의 4승 1패는 서로 다른 팀·난수·선수단이다. 이것만으로 전체 난이도가 맞다고 결론 내리지 않는다.

1.0.4에서 확인한 세 반복 요소는 후속 1.0.5에서 구현하고 재검증했다. 후속 검증은 실제 빌드한 Worker/D1의 로컬 분리 커리어에서 진행했다. 기존 공개 플레이 전체를 새 버전으로 다시 완료했다고 주장하지 않는다. 최종 검사와 공개 배포 식별자는 `WORKLOG.md`에 기록한다.
